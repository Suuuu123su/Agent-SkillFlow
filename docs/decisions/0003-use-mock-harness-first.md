# ADR-0003：第一版只使用确定性 Mock Harness

- 状态：已接受
- 日期：2026-08-24
- 决策任务：T02

## 背景

第一版需要验证安全语义、来源图、授权匹配和指标是否正确。如果直接接入真实 Agent 平台、LLM、网络或 Shell，平台差异、模型随机性和真实副作用会同时进入实验，无法判断失败来自语义实现还是外部环境。

## 决策

T01～T14 只实现最小 `HarnessAdapter` 接口和确定性 `MockHarnessAdapter`：

- Skill 行为由 Scripted Backend 驱动；
- 网络只写入 `MockNetworkSink`；
- Shell 只记录结构化参数，不创建子进程；
- 文件只位于 pytest 临时根目录；
- 用户确认和 Skill 撤销只由 Benchmark 特权接口执行；
- 攻击成功以 Mock Tool Receipt 判定；
- 固定 seed、时钟和 ID 工厂保证 Trace 可复现。

真实 Harness 只属于门控 T15，并且必须由用户单独授权。

## 理由

1. **安全**：没有真实外发、Shell 或凭据风险。
2. **可复现**：相同场景和 seed 应产生相同 Trace 哈希。
3. **可手算**：Effect、Grant 和路径规模受控，便于核对 UEA、HIAA、ALR、RIR 和 CI。
4. **可归因**：单因素开关的差异不会被模型采样或平台路由噪声掩盖。
5. **解耦核心分析**：核心模型和指标不导入具体 Harness SDK。

## 被否决方案

### 首版直接接入真实 LLM 和真实平台

无法保证确定性，还会扩大凭据、网络和平台权限边界；不适合作为语义 Golden 基线。

### 用真实 Shell/网络但依赖沙箱

完整 OS 沙箱本身不在 MVP 范围，且真实副作用对 T02 的研究问题没有必要。

### 只做静态 Trace 样例而不执行 Mock Tool

无法区分 Tool 请求、允许决策和实际 Effect，也不能用 Receipt 定义攻击成功。

## 后果

正面后果：

- T14 前可以完成安全、确定性的端到端验收；
- 每个数字都能回到 Event、路径和 Receipt；
- 对照实验可以严格保持能力匹配。

限制：

- MVP 结果是受控机制验证，不代表真实平台中的攻击发生率；
- Scripted 单次运行不能替代真实 LLM 多 seed 统计；
- 平台 Adapter 的插桩完整性需要 T15 单独评估。

## T15 启动门槛

只有同时满足以下条件，才可以请求用户授权 T15：

- T14 全部质量和安全验收通过；
- 真实 Adapter 的最小权限、网络和凭据边界已写清；
- 有 Mock 与真实 Trace 的字段对齐方案；
- 有可立即停止和清理的回滚方案；
- 用户明确批准真实 Harness Pilot。
