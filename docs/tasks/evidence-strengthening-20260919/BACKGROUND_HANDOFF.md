## 1. 用户在研究什么

项目为 `Suuuu123su/Agent-SkillFlow`，围绕 agent skill 投毒与安全。Skill 的文档、输出或记忆可能含恶意指令；问题不只发生在一条工具链上，还涉及 skill 与 harness 如何传递数据、使用权限、实际执行动作，以及记忆跨会话保留的影响。

用户希望构建一个系统性、可量化的统一框架 SkillFlow，把这些关系说清楚、记下来、验证出来。**框架是论文主线；Evidence 防御是框架的一个验证应用。** 用户不以“必须做出最强防御系统”或“多堆外部防御基线”为目标。论文面向顶会，需要真实的非平凡发现；修复代码缺陷、统一日志格式或提出三值判断本身不足以成为核心创新。

已确定的叙事顺序：

> 统一运行证据 → HIAA/ALR/RIR/UEA/Provenance/CI 机制测量 → P3/P3R 结果 → P4 证据消融 → P0 公开任务测量差异 → Evidence 防御应用。

本轮沿这条主线补强“什么时候证据够用、缺证时如何诚实判断、补证代价是多少”，不另起一条大规模防御研究。

## 2. 看懂仓库所需的几个概念

| 名称 | 在本项目中的意思 | 必须区分的边界 |
|---|---|---|
| Skill | agent 可使用的能力或流程包，包含说明、资源与工具使用方式 | Skill 文本自称“获批”不等于真实授权 |
| Harness | 连接模型、工具、上下文、记忆和执行控制的运行环境 | 同样的 skill 在不同接口下可能留下不同证据 |
| Artifact / Event | 数据的不可变版本，以及读取、派生、写入等事件 | 来源关系不能反向修改历史事实 |
| Effect / Receipt | 实际动作效果及执行回执 | 请求了工具、策略允许或模型说完成，都不等于动作真正发生 |
| Grant / Scope / Lifetime | 结构化授权、资源/动作范围和时间/会话有效期 | 数据可信度与授权权力是两回事；撤销和跨会话边界必须可追溯 |
| 观察证据 | 被测分析器和补证策略当前获准看到的记录 | 缺一条记录不自动说明事情没发生 |
| 独立参照 / oracle | 评估时依据独立实际效果和权限要求得到的答案 | 只能用于结果评估，不能泄漏给补证策略 |
| Full | 当前分析器看到完整记录时的输出 | 同一个分析器也可能错；Full 一致性不能代替独立正确性 |
| point / unknown / N/A | 确定判断、证据不足、合同不适用 | unknown 与 N/A 均不能算“正确”或“安全” |

源码语义入口：[docs/security-semantics.md](../../security-semantics.md)。该文档有较早阶段的冻结约束；本轮只新增版本化分析与独立实验，不改写旧规范或原始证据。

## 3. 指标在回答什么

以下是方便接续的解释，精确定义以[指标合同](../../../论文材料/P3_机制测量/p3r-20260917-103400/METRIC_CONTRACTS_P3R.md)为准，不凭本表自行重新定义指标。

| 指标 | 简单理解 | 当前主要边界 |
|---|---|---|
| HIAA | 用 target/neutral 与 bridge on/off 四格差分测量特定桥接的交互作用 | 必须使用同一资格规则和完整四格组；不是两种防御的 ASR 差 |
| ALR | 检查低可信文本的“授权声明”是否实际进入授权依据并促成执行 | 严格合同需要原时点原因及合法对照；不能从缺失日志补猜模型内心 |
| RIR | 检查撤销后跨会话是否仍有合格影响与未授权执行 | 必须说明记忆形成、污染前缀、到达和观察充分性；零值不证明撤销有因果收益 |
| UEA | 真实执行效果是否缺少有效结构化授权 | 要绑定 Effect、Receipt、Grant、Scope、Lifetime；不等同所有业务违规 |
| Provenance | 记录的数据来源和父边是否符合机械传播参照 | 记录器的数据血缘不自动等于语言层面的因果影响 |
| CI | 合法配对干预前后效果的有符号差异 | 旧中和有结构/语义问题；不能仅凭一对差异宣称一般因果结论 |
| TaskSuccess | 任务要求的真实产物或效果是否成立 | 必须检查产物、绑定和回执，不能相信文本宣告完成 |

## 7. 为什么还要做下一轮

审查认为当前方向仍偏薄，容易只是“同一个分析器读哪些字段”的复述。新一轮要补三个实质缺口：

1. **解释不完整。** 删 provenance 会连带清掉 counterfactual 内的 source_object，但当前缺字段列表主要只记录顶层读取。需要一份可核查的跨字段依赖与收费账本，防止漏报依赖或免费补回隐藏信息。
2. **参照不够独立。** 旧历史记录主要比较 Full，一致不代表正确；有限参照共享既有构念。需要来自独立实际执行/产物和权限记录的参照，至少覆盖 UEA、TaskSuccess。没有外部 harness 时可做独立沙箱，但须降级为受控跨实现验证。
3. **成本和泛化还未证明。** 旧实验按证据类别数比较，类别大小不等；初始字节和跨字段副本计费也不充分。应冻结任务家族留出，在一致总字节预算下比较强静态基线，加入整通道、随机和失败相关缺证。

期望发现的是能从实际执行/采集记录中核查的非平凡现象，例如表面上相同的调用记录，在落地效果、撤销时点或产物绑定上对应不同机制结论，以及哪组许可证据能消除歧义。例子只是预设问题，不是尚未执行就认定会得到的结果。

若动态仍没有优势，保留静态方案与负结果即可。若仅能完成独立沙箱验证，不能写跨真实 agent 平台泛化。若同字节优势消失，就删除效率优越性，只报告成本与覆盖的测量结果。
