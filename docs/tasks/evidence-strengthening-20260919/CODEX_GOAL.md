## 要完成的工作

**M0：先补测量基础。** 建立机器可核查的跨字段依赖映射，将投影、补证收费和策略可见依赖对齐。特别检查嵌套分支、重复证据、副本与共享通道。新增通道不能免费恢复另一通道收费的隐藏信息。让“为何未知、需要补什么”可以从证据路径核对；依赖表本身是实现支撑，不包装为新算法。

**M1：建立独立参照。** 优先复用已经可访问的外部 harness 和原始执行记录；核对真实执行效果、授权与撤销、任务检查器，不用当前 predictor 或 Full 输出来生成真值。若没有合适外部来源，实现独立本地沙箱执行接口与记录器，以实际沙箱状态变化形成参照，明确标为受控程序执行和跨实现验证。它不能冒充外部模型运行或外部 harness 的实证。

**M2：做公平且有留出的补证实验。** 按任务或构念家族分开开发与测试，冻结合同、策略和预算后再看测试结果。纳入整通道缺失、随机缺失、失败相关缺失；第三类是人为压力条件，不声称测到了真实缺失分布。强基线是开发集上冻结的按指标静态顺序。在一致的总字节预算下比较，初始证据也计成本；证据通道获取次数仅作辅助。预算、随机种子和同任务多查询均是重复测量。

**M3：根据证据决定贡献。** 主结果要回答两个问题：独立执行来源上的判断是否可靠；公平预算下哪些证据组合可恢复正确判断。动态策略作为可选扩展，先让强静态基线和独立参照通过。动态没有优势就保留简洁静态方案；结果不支持的贡献必须降级，不能反复调测试集直到得到正结果。

动态是否运行及其策略须在 R006 冻结，R007/R008 使用同一次封存留出评估；不得看完静态留出结果再设计动态策略。

准确实验矩阵、预算、文件名、统计方法、停止条件以本目录 `refine-logs/EXPERIMENT_PLAN.md` 为执行依据。本 GOAL 不授权超出该预算的自动扩跑。
