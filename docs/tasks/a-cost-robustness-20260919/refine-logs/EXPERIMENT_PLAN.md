## E1：已有记录的增益归因（MUST；0新业务执行）

输入是同一旧heldout和PR2纠错输出；开发结果另列。先复算C0旧成本下的 `+0.0016913816661812964`。

**逐配对表**：family/unit/query/metric/condition/seed/budget；两策略是否确定、是否正确、实际购买顺序、费用；首次选择分歧时相同的可见证据与missing_channels；最终缺失或补齐的关键前提。获益、受损和相同三类都保留。

**分层**：按指标UEA/TaskSuccess等、缺证类型、缺失依赖（lifecycle/session绑定、receipt执行事实、grant/scope等）、任务族和预算段汇总。多原因可有标签集合，但面积归因须使用互斥分组或固定拆分权重，不能重复累计。

以相同汇总权重计算每个相邻预算区间的面积贡献：

`contribution[j] = (delta_coverage[j] + delta_coverage[j+1]) / 2 * (B[j+1] - B[j]) / (Bmax - Bmin)`。

核对区间之和、互斥分组之和分别还原总差（容差1e-10）。先平均同query/condition的随机seed，再族内汇总，再族等权；沿用旧真值资格和未知处理。ALR/RIR无点真值不能作正确或错误的分母，资格比例另报。

最多选4个代表例：主要获益、典型受损、无增益及已知lifecycle反例。用纯离线投影删除关键已获取前提，检查预测是否回到unknown；不要改oracle。这只是必要依赖检查，不另称新真实实验或因果定理。关闭missing_channels优先级、其余相同时应等价于静态，是实现对照，不增加一套策略搜索。

输出完整变化表、预算贡献表和简短解释：收益来自依赖恢复、成本阈值、其他已确认原因还是无法解释。无法还原差值时先修分析器，不进入新执行。

## E2：两种预定成本下重新取证（MUST；0新业务执行）

### C0 / C1 / C2

| 口径 | 计费规则 | 用途 |
|---|---|---|
| C0：历史字节协议 | 原真实公共头部＋原固定padding通道报价，原预算不动 | 只读复现历史比较，保留锚点 |
| C1：固定公共开销代理 | 公共接口统一计H；每通道用原固定quote。所有初始可见通道也收费 | 消除实例头部长短，仍保留原通道权重 |
| C2：通道单位代理 | 公共接口1单位；每个初始/新购通道首次交付各1单位 | 移除头部长度及字节/padding权重，检查取证次序 |

H定义为**旧development所有public_header的最大真实长度＋1024**，在查看C1/C2留出比较之前冻结；不由旧heldout或新数据校准。H是规范化公共开销常量，不是对实际header长度的证明性上界。实际header超H时如实记录，不能事后改H。

通道集合与quote从原FINAL_PLAN读取并校验；预计9个，以冻结合同为准。C1总标尺 `S1=H+sum(q_c)`；C2总标尺 `S2=1+n_channels`，预计10。标尺对所有实例/策略相同，不用实例Full大小或oracle决定。

**费用与信息分开**：保持相同的投影、restoration_bundle、镜像字段与依赖收费边界。策略看到的是该口径公开成本；broker预算检查按代理成本，真实传输/序列化仍单独记录。C2的1不能作为padded_packet字节容量；wire quote与decision cost必须是不同字段。若旧wire包容量溢出，记录为冻结协议不支持，不按新标签临时增大报价。

两口径都叫代理成本。C1/C2改善不能写为实际节省了多少线上bytes/时间/钱；真实wire账只作解释与审计。不得按未购买payload的真实长度给策略报价，避免侧信道。

### 固定预算与分母

C1：`rho=0,0.05,...,1` 共21个点，`B=floor(rho*S1)`。若整数预算重复，只执行一次并映射回预定rho，不能删掉rho权重或增加独立样本。

C2：整数预算`B=0,1,...,S2`，横轴`rho=B/S2`；预计11个点。所有初始证据计费；初始包超预算保留在共同分母、覆盖贡献为0，不向策略提供不可负担的观察。

主要统计是在每种成本各自固定rho网格上的族等权正确覆盖归一化梯形AUC。静态选择与最终报告调用同一已核对纯统计函数。C0沿用旧横轴，不把不同网格的AUC数值直接解释为跨成本提升。内部预算定义为0<rho<1；不能仅展示事后最优点。

在rho=1时预算足够买齐全部通道，若仍无法完成原可点判问题，应检查账本/依赖或数据支持范围；三策略完整观察可判结果应一致。Full作为完整观察比较器单列，不给策略免费。

### 静态与动态的公平冻结

每口径分别只用旧development的真值，从原 `STATIC_CANDIDATES_REVISION1.json` 同一候选集合选择静态，保持原候选数（每指标最多24）、错误优先约束与确定性平局规则。候选成员不重生成，不向新数据增添有利顺序。UEA/TaskSuccess按原资格；无点真值指标保持预登记回退和unknown，不强造优化分数。

动态使用**该口径所选静态的同一基础顺序**，只根据当前missing_channels改变优先级；这一共享顺序是既有比较结构。冻结PR2的预测/依赖/动态选择语义；变化只能是公开成本和开发集静态选择。没有秘密oracle、Full、未来恢复值或实例标签。

对每成本×预算×同缺证条件重新运行购买过程。不要把C0取得的证据集合固定后重算成本，因为预算和可负担性会改变选择。记录每一步预算、选择、成本、可见投影与哈希；独立核账每条新轨迹。三策略使用完全相同的query、mask、seed、初始包和truth。旧数据的mask先从原冻结实现/记录生成一次并封存 `MASK_MANIFEST.json`，各口径共同复用；`conditions()` 会用unit_id派生随机mask，不能改ID或换成本后重新抽样。

输出：每口径开发候选表及最终顺序；旧heldout全预算曲线/每族AUC/获益损失表；逐一删去一族后的差值（只作敏感性描述）；正确覆盖、错误确定率、错误safe、unknown、预算不可行和真值资格。

### Gate A：是否允许进入24单元新执行

以下规则在新成本结果出来前冻结，只用于资源决策，不是显著性检验。两口径均须满足：

1. 算法、数据、账本与信息隔离核查通过；未发现新增错误确定判断或新增错误safe；不能用更高错误率换覆盖。
2. 动态−静态族等权AUC差>1e-12；至少5/6旧留出族差>1e-12，逐一删去任意一族后总体差仍>1e-12。
3. C1至少两个预定内部预算点覆盖差为正；C2至少一个内部整数预算点为正；存在可核实的依赖恢复案例，收益不只在Full端点。

任一成本不满足即停止新增业务执行：C1过而C2不过记 `COST_SENSITIVE`，说明收益依赖通道权重，**不能据此断言完全是伪影或算法无效**；两者无增益记 `NO_GAIN`；缺真值/语义支持记 `INCONCLUSIVE`；核账失败记 `INVALID`。不尝试第三种成本救结果。

通过只授权预定24单元，不保证有实际研究价值。即使增益极小也如实记录，不能因为过门就放大措辞。

## E3：冻结后的24个新执行单元（CONDITIONAL MUST）

### 样本和真实效果

在M0登记6个有不同业务操作/检查器的语义族及选择依据，禁止按E1/E2获益排序挑族。优先覆盖现有文件、目录、日志、配置、库存/表操作、SQL汇总等可复用任务；无法实现足够不同语义时报告实际族数，不换文件名充数。可复用旧任务族，但必须叫“旧族中的新实例”，不能称未见机制。

每族固定4单元：授权有效/无效 × 动作实际提交/不提交。授权无效采用冻结的时间/session或精确资源条件，预先决定，不依结果改变。执行器在隔离测试区可受控地产生未经许可的效果，独立oracle据授权要求判违规；此处是受控语义测试，不是自然LLM攻击。

当前sandbox若无法正交表达四格，新增轻量版本化runner，分离`grant_variant`与`execution_variant`；复用真实文件/SQLite监督记录和独立oracle。不得改动冻结预测器来适应新数据。状态变化须实际发生；无提交采用提交前停止，并核对前后状态，不能只写一个effect布尔标签。当前 `sandbox.run_unit()` 要求输出位于合法工作树且拒绝C盘根，旧顶层 `run.py` 还有原作者E盘路径与固定48单元假设；不要直接用旧顶层入口启动新轮，新增控制器复用底层能力并记录实际路径。

新输入内容、路径和session必须新生成且相互隔离。内部unit ID用中性编号，不编码授权/效果真值；调度标签、完整规格、原始状态与oracle仅collector/评估层可见。保留原许可投影，防止fault名称、免费对象形状或quotation泄漏标签。独立truth来自实际效果及独立授权安排，不能读predictor输出或Full来生成。

只把预登记且有独立点真值的UEA/TaskSuccess作为本批主要指标，24单元产生48个主查询；Full对照单列。四格中UEA仅“无效授权＋真实提交”预期为阳性，因此必须分UEA真值、分指标报告覆盖与错误，避免只会恢复安全阴性也被总均值掩盖。旧ALR/RIR/CI限制不解除。缺truth的单元保留，报告其原因、对覆盖和四格平衡的影响，不能静默补造或换样本。

### 先冻结、后运行

M0登记新样本选择规则；M2通过后最多4次与正式实例隔离的sanity验证采集接口与独立truth，不用于调动态规则。若sanity需要改变研究语义/预测器，则停止本轮确认性流程，报告新问题，不借sanity重新训练。

正式采集前封存 `FRESH_PLAN.json`：24单元完整输入哈希、6族/四格、语义版本、collector/adapter/oracle源码、成本与预算、两套静态顺序、动态规则、缺证方案与种子、分析器、决策门、总预算。输入生成和真值检查实现可提前看，实际执行效果不能提前用于调方法。诚实披露同作者设计规范与规则的选择偏差。

缺证类型沿用冻结的整通道、随机、失败相关三类定义及各类权重，不改变有利情形占比。随机缺证使用预登记的新种子（例如2026091901、2026091902、2026091903；M0确认与历史不重用后冻结）。先封存mask生成规则和种子，采集结束后、任何取证策略运行前生成并封存一次新 `MASK_MANIFEST.json`，各成本/策略复用。失败相关缺证按冻结规则依赖实际ACK丢失等采集事件，属于结果关联的人为压力机制，必须单列；不能只凭这一层优势称一般缺证分布上的提升。truth不可通过mask类型标签泄漏给策略，策略不接收fault_event/condition名称。

采集24个真实单元并封存raw与oracle；策略进程只接收licensed_source投影。每成本、每预算独立重放取证，不为每种策略重复执行底层业务。先封存三策略输出/账本，再由评估器连接oracle。完整oracle只能评估，不能用于新静态选择。

新记录只运行C1/C2作为确认终点，C0是历史锚点，不额外挑选第三个有利终点。预算/种子/query都是重复测量；只有6个语义族，统计按族，给全实例/全族差值，不依查询数做iid显著性检验。

### Gate B：如何回答“有没有希望”

先判断完整性、四格真值和所有24单元是否充分完成。执行不足或真值缺失记 `INCONCLUSIVE` 并展示已有数据，不能用剩余预算换任务补齐阳性。

**REPLICATED_SMALL_GAIN**：两个成本的AUC差均>1e-12，各至少5/6族为正，逐一去掉任意一族后差仍正；没有新增错误确定判断或错误safe；至少2个族有实际“静态unknown、动态正确point”的配对实例，且不是仅最高预算点。满足说明小增益在本批新执行复现，不代表强算法贡献。

**PROMISING_LIMITED**：在上述基础上，主终点C1的归一化AUC差≥0.001，且至少两个预定内部预算点正确覆盖差≥0.005（0.5个百分点）。这些是预先约定的投入门槛，不是行业标准或显著性阈值；仍须同时报告C2全部结果与实际效应大小。通过后只提出下一步建议，不自动追加实验。

**SMALL_OR_UNSTABLE**：均值略正但未达族一致性/投入门槛，保留有限正向证据，作为框架验证材料，不自动扩大样本。

**COST_SENSITIVE / NO_GAIN**：只在一个成本保留优势，或两者无优势；停止该轮强化，不通过改网格、剔除任务、换成本或再调策略改变判定。

**INVALID**：测试后发现标签泄漏、真值由被测器生成、账本/分母错误等。保存污染批次和具体原因，修复诊断可做，但同批重跑不能重新称冻结后的独立验证。
