# P4实验协议：固定事实，改变证据可见性

## 1. 研究问题

P3回答“能够测出哪些机制量”；P4回答“这些判断需要哪些证据；删掉它们后系统是否还能可靠地表达已知与未知”。

本轮只干预测量视图，不改变世界状态，不测新攻击成功率，不模拟“没有防御时模型会怎么做”。已有original/identity/neutral是事实数据；再次读它们不是新反事实实验。

## 2. 三个严格分开的数据域

**A：已有受控构念。**使用P3-R显式状态机/有限模型及T18可追溯正负例。真值由独立评估器用已冻结规则与发生的事务求解，不直接读生产指标输出。允许纯符号状态枚举，不调用World.invoke、业务执行器或模型。用来报告可判断性、正确/错误确定结论和区间包含性。

**B：历史Live。**T17 F/G/H及P3-R实际Live全量符合范围的事实。报告各视图可计算性、结果/区间变化、适用性和具体证据；没有独立真值的量不报告“准确率”。生产来源标签与Oracle不能互相混入。旧CI仅作版本化探针/敏感性；完整视图也允许其精准控制归因为unknown。

**C：P0/P2开放任务接口。**仅复用已经整理的字段/标签用于解释适用性，不重新标585条，不把Codex辅助标签当gold；最多选6个已有案例说明证据层次。不建立第三轮全量语义实验。

每个域独立表；不能把A的漂亮准确率与B的规模合成“Live识别准确率”。

## 3. 13个固定视图

|ID|视图|移除的语义证据|应保留的独立信息|
|---|---|---|---|
|V00|FULL|不额外移除，但仍无评测标签/gold/旧计算值|已有许可事实全部可用；历史缺失不补|
|V01|NO_RECEIPT|真实执行回执及相同回执的拷贝、派生verified标志|提议、参数、独立文件前后状态、完整观测边界|
|V02|NO_GRANT|结构化Grant内容、快照、等价副本；从它派生的授权结论|任务文字、动作、原本存在的其他独立事实；文字不是签名Grant|
|V03|NO_PROVENANCE|来源身份、父边、派生/decision_basis关联及其派生图缓存|业务内容、能独立证明的对象效果；不删除对象正文|
|V04|NO_COUNTERFACTUAL|identity/neutral分支对应、结果、干预有效性及由它生成的confirmed influence/CI|原始运行的可见来源与实际效果|
|V05|NO_TASK_EVIDENCE|任务成功证书和缓存结论、由其派生的satisfied/U/STS|原公开任务与实际交付物；可由机械事实独立复算的义务仍可判断|
|V06|NO_LIFECYCLE|撤销事实、Session偏移/映射、生命周期联系及派生stale/current结论|已发生Effect和不属于该家族的时间/对象事实；不能靠文件名猜Session|
|V07|NO_SCOPE_LIFETIME|Grant/Manifest中的范围、用途/有效期限制及等价投影|结构化Grant是否存在、动作与独立事实；缺字段不是wildcard|
|V08|NO_DECISION_REASON|原时点reason与基于该reason的直接副本/分类|实际请求、真实Grant、Effect、其他条件|
|V09|NO_FAILURE_TYPE|格式拒绝、截断、拒答、infra等细类及对应原因文本|独立记录的完成/观测范围与已发生效果，不连带清除全部日志|
|V10|NO_CAPABILITY_RULES|有限域桥梁/转移/AND/执行/授权语义中受测规则族|已知效果全集、非负权重、已知其他声明；规则空间不再假装闭合|
|V11|IRRELEVANT_META_ONLY|机器昵称、展示标题等确认为无语义的信息|所有测量所需事实；期望相关结论保持|
|V12|OPAQUE_ID_RENAMING|无信息删除：全域一致双射替换纯身份ID|关联和去重关系；业务ID/URI/权限/内容不可任意改|

10项主消融+2项负面对照+Full=13。不是所有指标都会受每项影响；不相关应不变。V10对没有能力声明的历史记录仍记录“原本无此域”，不免费补一套假声明。

V02对Grant的删除覆盖其scope信息；V07只删范围/期限用于更细定位。两种有意的嵌套消融单独标明，不能当正交因素求独立贡献总和。

## 4. 遮蔽与独立重建：避免两个相反错误

**错误一：只删一列，答案从缓存漏回来。**比如删除grant表，保留decision.authorized或旧ALR七条件，分析器仍拿到结果。这不是消融。

**错误二：连所有结果事实都一并删除。**比如撤销不可见就连实际发送也删掉，导致风险全面未知。这不是单证据消融。

每个字段先标为：原始证据、同义副本、依赖该证据的计算缓存、独立证据、仅评估标签。mask删除目标家族和对应副本/缓存；**实际世界中的后续事件不是因为因果上受影响就自动删除**。同一个字段在不同数据源中可能角色不同，映射到文件+JSON指针+依赖来源，不按键名全局猜。

独立可见事实有合法证明规则时允许恢复，例如任务明确要求文件含两项内容，而可信文件后像与写入记录齐全，去掉task_success.json后可以重新核对。必须记录`reconstructed_from_visible`和证据路径，不能以“猜得到”为理由伪造严格Receipt或Grant。

strict VerifiedEffect要求同Run Receipt时，独立diff仅证明相应文件变化，不能悄悄改strict定义；可另报`observed_file_change`。Receipt本来定义为可被多种可信签发记录证明时，等价规则必须先在合同中冻结。

## 5. 输入、预测、参照三层隔离

```text
只读原始包 → 可信输入检查/哈希 → 纯证据投影 → 视图专属分析器
                    ↓                              ↓
              独立参照/查询元数据              预测落盘封存
                    └──────── 只读比较器 ←─────────┘
```

预测器只拿投影文件或只读EvidenceView，不拿全量state对象、根目录、expected或gold句柄。view_id可用于缓存和审计，不允许`if view==NO_GRANT: return unknown`这种预设结果。状态必须由实际可得的谓词组合产生。

P3-R `state.json` 含`scenario`、`grants`、`events`、`artifacts`、`revoked`等多处副本；事件内还可能含grant_snapshot、authorized、matched_grants。`scenario.policy`、positive/negative路径名、index.expected、pot.result应拆出预测路径。合法声明的引擎规则可作为合同输入，但不能用测试case的预期机制标签判答案。

所有视图从同一immutable基底独立生成，不能先Full缓存后Mask命中。尽量由干净子进程只读view目录；输入投影过程中不修改原hash链。原链完整性先验证，新view记录自己的hash和原证据来源；有意缺省不算损坏原运行签名。

若有许可信息以多条形式存在，按03第4节区分重复证据与独立替代，不把读取了合法替代误报泄漏。写出`MASK_DEPENDENCY_MAP`和实际读取审计。

## 6. 固定查询集合，不按新结果换分母

每个查询唯一键由`study / protocol / metric / unit_kind / unit_id / selector / horizon`组成。同一事实可能支撑不同指标，但计数单位仍不同：UEA操作、ALR请求、RIR链会话、CI分支组、HIAA四格、来源成员。

控制器冻结所有查询，13视图都写一条结果或明确状态。记录eligibility=true/false/unknown；缺失生命周期导致eligibility未知，不能变成“无撤销、不适用”后被移出报告。

HIAA先保留四格的原计划Run和结果，再聚合；分析器不能看到“目标Skill”就自动Y=1。聚合器可使用合法实验分组账本，不得把该分组当输出答案。

共享前缀和同Session多效果需要依原指标去重。Full与Mask是同一运行的分析复制，不增加Live样本数，不作为独立抽样做显著性。

## 7. 合同保持与部分证据推理

保留原legacy指标表；新分析层以`P4_PARTIAL_EVIDENCE`单列三值或范围。不可计算不是数值0。旧Strict与P3-R附加identity门分开，每个查询绑定真实合同。

布尔合取：任一已知false使整体false；全true为true；其他unknown。合取前还需检查适用性/单位是否可确定，不允许用同名但别的请求的false来短路。

数值结果分为精确点值、有效范围、无识别范围、证据矛盾；“真实不适用”和“资格未知”另存。Full也可以unknown；P4不是将P3遗留NA强行消除。

## 8. 消除循环论证的最低要求

A域参考用独立状态转移/事件检查和明确合同。Full并不预先定义为100%正确；任何Full错算先保留并解释。生产与参照共享解析器可披露，不能共同调用同一核心函数再称独立。

从既有有限构念中寻找最多6对“删证后许可观察相同，但独立真值不同”的对照。如找不到，不虚构已存在匹配对；可以记录有限声明模型的两个相容补全作为**符号不可辨识见证**，不执行业务工具，不计Live样本。

另保留“存在冗余独立证据，删一个证书仍能判定”和“已有false条件使某个缺证条件不再影响整体”的反例。不能把声明依赖表写成实际实验结果。

**合同依赖不等于框架独有必要性。**若某指标按定义就必须有Receipt，那么删Receipt后该指标不可计算，首先说明定义依赖；不能只凭这一点宣称SkillFlow优于所有日志系统。需要把定义依赖、实际不可辨识见证、独立替代可恢复的比例及错误确定结论分别报告。P4证明范围以这些实际证据为准。

## 9. 有效性与不利结果

13视图只做单族消融和负对照，不扩成所有证据子集。确有耦合难以归因时列GAP，不临时组合几种删法去追求差距。

在一致事实和健全推理合同下，更少信息不应凭空提高确定性；出现unknown→point或true→false等变化需区分纠错、冲突证据消除、资格变化和实现泄漏，不能直接当测量改进。该单调性不是对任意冲突日志的无条件断言。

最后只主张测量可辨识性，不把unknown增加写成攻击增加，不把更窄区间写成更强防御，不将受控有限模型正确性扩展成自然语言语义真值。
