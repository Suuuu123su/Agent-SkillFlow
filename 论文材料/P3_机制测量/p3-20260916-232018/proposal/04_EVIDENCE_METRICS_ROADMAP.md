# 后续规划：让框架指标与Evidence选择形成可检验联系

**本文件是本次新增的设计提案，不是原论文、当前实现或已完成实验结果。P3只归档与静态映射，不实现新算法。**

## 1. 是否有必要改Evidence？

有必要考虑一个小而清楚的接口增强，但不必把所有聚合指标硬塞入Router，也不是框架论文成立的前提。

若论文仅声称“框架运行证据可被防御消费”，现有原型与真实干预已经对应这个应用问题，保留限制即可。若要声称“机制画像影响防御选择”，则必须补上可追溯的画像输入、适用范围及从输入到动作的验证，现有ASR表不能替代。

已核对的CT v3入口以当前任务、可见来源、对象种类、跨Session标志和意图推断选择Content/Derived；没有显式HIAA/ALR/RIR数值输入。[S3] 因而现阶段应叫“局部证据驱动”，不能回溯称历史结果来自本文件提出的画像路由。

## 2. 先分开三类信息

|信息|何时可得到|怎样使用|
|---|---|---|
|当前事件前缀的事实|当前决策前真实可见|对象身份、来源、版本、当前授权、实际依赖、失效通知、候选差异、必要内容；可用于具体边界判断|
|已冻结开发/校准集的机制统计|测试之前，从其他合格运行算出|HIAA/ALR/RIR、覆盖、分母/区间及适用配置；只作为审查重点或次序的先验|
|当前测试的最终效果/评测答案|当前动作之后，或只在离线侧|最终ASR、UEA、STS、未来Receipt、当次ALR/CI/RIR、攻击标签；禁止作为当前选择答案|

HIAA需要四格；ALR需要原始/有效中和及原授权机制证据；RIR需要撤销后特定会话。它们通常不是单步特征，也不是“本条攻击概率”。过去已发生的效果可以成为以后步骤的事实，但不能回填到之前决策。参考配置/训练数据发生变化则旧画像的迁移支持重新判断。

## 3. 建议的新原型：Evidence-Profile-v1（独立命名空间）

不要复用曾被废弃的v4/v7/v12编号，历史v3不变。

```text
P3/P4验证后的开发集机制画像
  （版本、来源、分母、不确定性、适用配置、截止时间）
                       +
当前合法可见事件前缀
  （来源、对象/版本/用途、候选变更、授权与生命周期）
                       ↓
        画像适用性检查 + 机制假设/审查义务
                       ↓
    选择Content/Derived、作用边界和需核对证据
                       ↓
 同一冻结组件库 → 同一合并与执行器 → 实际效果
```

形式仅作接口约定：`plan_t = Router(local_view_t, compatible_profile_or_none)`。不是未经校准的加权安全分或攻击概率模型。

画像只告诉系统“哪里值得审查”，不提供“这份文件恶意／这个动作已获批准”的答案。任何拒绝、改变、失效或恢复仍须当前对象级证据和已有合法权限。画像低值/0不能放松当前硬约束；画像缺失不能自动全删或全开。优先回落到冻结的Local-only策略。

## 4. 每个框架量怎样连接选择

|量|合理连接|不合理连接|
|---|---|---|
|Context / Tool Return HIAA|若兼容画像提示特定桥梁有交互风险，且当前实际走该桥梁，优先审查对应来源及派生使用|从当次C/P/S生成HIAA；HIAA>阈值就认定当前文档恶意|
|ALR|对当前可见的低可信授权声明，检查声明到授权判断的提升；具体Grant仍按当时可信事实|读到“批准”就给ALR=1；历史ALR高就拒绝用户真实批准|
|RIR(1/3)|在当前确有相关撤销与依赖使用时，优先重验后继对象的受限用途|仅因Memory较旧或RIR未知，删除全部Memory和合法历史|
|UEA / Scope / Lifetime|将当前候选与真实有效授权绑定；过去确认的无授权效果用于审计，不代替前置政策|将未来Effect或P0业务错误当作当前无授权真值|
|Provenance / Decay|使用当前实际缺边/丢失来源状态决定补证；开发集追踪质量只提示可靠性|无独立GT时生成在线F1，或因来源Precision=1就自动授权|
|CI|兼容开发集的已确认影响用于确定重点机制；当前仍只称候选影响直到有效验证|把一条可达路径直接说成当前Artifact的因果影响|
|TaskSuccessEvidence|在候选变更前保留已知必要义务和合法状态，未完成部分仍有真实反馈可继续|读取本测试最终U/STS或正确答案指导执行|

非零HIAA并不告诉我们某个检查器一定有效；它只是目标系统机制的观察。选择器需要明确组件能力边界，不能从风险画像直接推导防御处理效果。

## 5. 新算法不先改组件能力

第一版只增强输入/选择接口。Content、Derived、输出合同、合并器、可用动作、原生底座、恢复能力及Actor资源在比较双方一致。

不得给Profile组独有的新Gate、更多工具、正确授权表或恢复提示，否则测到的是新增能力而不是画像信息。若组件看不懂新证据，两组同样升级该接口后再比较，完整标记新版本。

没有真实生命周期工具时，选择器最多要求已有Derived核对现有资料或报告不支持；不能宣称已经执行了撤销传播清理。旧系统最低效果审查要求在两组都保持，不因画像低风险而删除。

候选规划记录应含：`event_prefix_hash / artifact_id / version / use / boundary / profile_id / profile_compatibility / used_metric_fields / used_evidence_ids / selected_components / fallback_reason`。这些是建议字段，不伪称仓库已经实现。

## 6. 数据泄漏和迁移控制

画像按完整模板/Skill家族及所有派生、Session、seed和重复分组；开发与测试必须隔离，不能把同模板另一seed当独立未见任务。P0/P2的39阶段已反复用于诊断，不称新的盲测池。

画像必须记录：来源run集合、截止时间、模型/服务配置、harness版本、bridge定义、方法版本、指标合同和有效分母/缺口。

T17的结构化四格画像不能直接量化预测ClawTrojan当前任务；模型名相同也不足以兼容。若本轮没有兼容校准数据，应返回`PROFILE_NOT_APPLICABLE`，做定性“机制映射”说明而不是偷换成数字画像。

不使用测试case_id、攻击family标签、旧Judge结果、干净原件、未来step、当前被测分支的最终指标来取表。当前源码仍包含测试标识时，选择侧只用于日志外部绑定，不作为路由key。

## 7. 后续阶段安排（保持原编号，增加可选分支）

|阶段|目的|新实验模型请求|当前状态|
|---|---|---:|---|
|P3-FRAMEWORK-METRICS|恢复核心指标；附静态Metric→Decision图|0|本轮执行|
|P4-EVIDENCE-ABLATION|同一事实集合的测量视图消融|0|下一任务，未启动|
|P5-TARGETED-GAP|只补必要四格/反事实/真实撤销缺口|另行批准；旧≤68设计上限不是授权|按P3/P4缺口决定|
|P5-RX0（新增）|画像适用性/在线字段分离、算法设计与局部确定性检查|0|可选，P3之后再明确启动|
|P5-RX1（新增）|相同组件能力下的小型Local-only / Profile比较|需新授权，建议≤28目标单元|RX0通过且兼容画像存在才考虑|
|P6-PAPER-INTEGRATION|先机制表，再测量研究，最后防御应用|0|不受可选RX正结果约束|

不新增DASGuard必做项，不恢复P1，不增加第四个模型。P5的68与RX1的28是两个备选阶段的设计容量，不是当前可累加消耗的配额。

## 8. RX0：先证明连接真实存在，不追求新ASR

只做隔离的纯策略原型和确定性局部检查，不调用旧语义模型。至少检查：

- 不兼容或空画像按预定策略回落；相同语义下改无关ID/元数据不改变动作。
- 高HIAA只有在对应桥梁/使用出现时才影响审查重点，不能给所有任务同一个双开答案。
- 历史高ALR不能否定当前有效授权；撤销作用域不相关时不错误失效。
- 移除相关画像字段后，若选择改变，保存具体字段和选择链；若不变，如实说明该画像无增量作用。
- 原始事实可见范围、缓存和组件读取没有把遮掉的信息补回。

这些只是接口与局部机制验证，不声称新Actor执行结果或防御因果收益。最多约12个局部状态足够，不能又发展成大型自建攻击矩阵。

## 9. RX1：只有必要时做一次小试

建议6个预登记合格任务/起点（4个机制挑战、2个合法对照）×2配置×2次=24目标执行，另最多4 TECH，总≤28。这是假设有足够真实、合格输入的草案，不要求现在构造或跑。

两配置使用**同一新版策略框架/组件/执行器**：

- `Evidence-Local`：仅当前局部证据，画像输入为none。
- `Evidence-Profile`：局部证据相同，另有与测试隔离且适用的已冻结画像。

不以旧v3历史结果充当新Local对照。可以附历史All作背景，但无需新增All/外部基线。所有模型角色使用届时实际可用并明确获准的同一Luna接入；不能绕过GLM额度或用未授权备用端点。

主问题是“画像是否改变有依据的选择、该选择是否实际实施、风险与任务终点怎样变化”，不是只统计Token节约。保存计划、组件输入、真实处理、效果/任务端点和未知；没有新的终点独立判据就不自封安全成功。

全都无差异或Profile更差也完成；只得到局部选择变化时只写决策可用性，不能叫性能提升。条件不支持则保持未执行，框架论文继续用已有应用验证，不无限补样。

## 10. 论文表述边界

当前可写：Evidence原型消费SkillFlow提供的来源、对象与使用证据，在多个边界执行检查。

RX0后可写：设计了将离线机制画像与在线事件证据分离的决策接口，并验证限定状态下的输入/选择关系。

RX1合格后才能按实际结果讨论画像的下游实证作用。不存在“只要加了HIAA字段，就证明HIAA提升防御”的逻辑。

核心主文不变：**机制量化和测量正确性在前，防御与其指标连接是后部应用。**
