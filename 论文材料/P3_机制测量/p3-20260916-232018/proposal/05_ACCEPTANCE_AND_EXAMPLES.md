# 验收与好坏例子

## 1. P3完成标准

|方面|本轮需要的证据|不能替代它的东西|
|---|---|---|
|输入覆盖|全部相关分卷、分域数量、唯一ID与实际缺口|只看README或首卷|
|合同|逐指标原定义、分母、证据条件、代码版本|使用一个“通用风险率”|
|主结果|HIAA/ALR/RIR等真实计算与缺失解释|全填null或只统计ASR|
|复算|结果先落盘，再与旧报告比对|读旧分数生成同样数字|
|独立检查|独立逻辑核对核心条件与汇总|两个进程调用同一函数|
|真实性|零/负/未知/失败和不利结果齐全|补成期待正值，修改旧记录|
|框架贡献|机制区分、质量与覆盖分别陈述|HIAA高=框架准确率高|
|接口审查|源码路径和实际字段、最多6个保存边界|执行Router模型重新生成解释|
|范围|新实验调用0、原数据未修改|离线名义下开启SDK或业务工具|
|交付|指标、证据定位、分析代码、报告与新对话交接|一页结论或只有脚本没有结果|

`P3_STATUS.json`应分别报告data_coverage、metric_recompute、independent_check、semantic_validation、paper_readiness、live_requests与unresolved_items；允许`COMPLETED_WITH_DOCUMENTED_GAPS`，但不能把无法复算的核心值标成已确认。

## 3. 论文表里哪些解释必须保留

**T17的风险不是框架错误率。**它测量模型/服务配置下的机制行为。来源精确率、绑定覆盖、独立核对和不能判断的数量才是另一类测量质量信息。

**P0辅助语义不是金标准。**人审0继续明确，不能用于训练新画像又同时评估同一批测试。

**P2不是统一条件路由因果实验。**可引用真实双检查与正反案例，但不回填进HIAA/ALR/RIR主表。

## 4. 交付后的停止与复查

本轮不以假设获支持作为完成条件。复算有差异就列明新旧值、原因与需要审阅的最小证据；缺文件就给定界检索范围和缺口，不开启旧模型任务。

最终新对话交接必须写：完成哪些表、哪些是报告转录/事实复算/独立核对；未判语义与缺口；新模型调用是否确为0；P4与P5-RX等仍未启动。先交审查包，不自动上传。
