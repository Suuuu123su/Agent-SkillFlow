# P3-R：机制指标补全，不再只列缺口

**交给本地 Codex 的新任务。**目标是把 P3 剩余的可修复问题做成实现、数据和论文材料；不是声称这个任务包已经完成实验。

## 本轮的实际顺序

1. 从原始记录定位 M2 为什么没产生 Memory，并修正新的测量入口。
2. 完成 HIAA_pot 的有限声明能力空间分析、ALR 原因证据、RIR 分母与 T18 正反例、CI 稳定性及独立核算。
3. **只有历史证据确实不够时，执行限定的 Luna 机制补实验**；不把不存在的历史响应补出来。
4. 生成“历史旧口径 / 修订计算 / 新构念验证 / 新 Live 补实验”四层主表、对应源码与可复核证据。

P3-R 是对原零 API P3 的明确扩展。原 P3 的零调用和完成状态保持原样；新增本地执行、新模型请求记入新阶段。P0/P1/P2不重做，Evidence动态算法不改，P4和画像路由只保留后续计划。

## 文件阅读顺序

- `01_CODEX_GOAL.md`：完整目标、背景、执行权限和启动消息。
- `02_OFFLINE_REPAIR_SPEC.md`：五项实质补全工作及具体验收。
- `03_LIVE_SUPPLEMENT_SPEC.md`：可跳过的最小 RIR/ALR 新实验，包含前缀和分支。
- `04_ACCEPTANCE_AND_EXAMPLES.md`：好／坏例子、阶段完成条件、最终报告。
- `plan.json`、`capacity_slots.csv`：共享容量与固定槽位。
- `references/`：本次 P3 原报告、外部复核、精确缺口与合同差异，原文副本。
- `locators/`：从本次 P3 中提取的历史 M2 定位键，**不是新实验样本或在线答案**。
